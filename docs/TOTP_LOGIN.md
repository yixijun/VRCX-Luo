# TOTP 密钥与验证码

登录后的「设置 → 系统 → TOTP 密钥」可为当前账号保存、替换或移除密钥，并查看当前一次性验证码和剩余秒数。验证码每 30 秒更新；离开设置后销毁组件会清除内存中的密钥和验证码。登录页已保存账号旁的钥匙按钮也提供同一管理界面。

支持 Base32 密钥及使用 SHA1、6 位数字、30 秒周期的 `otpauth://totp/` 链接。此功能使用已在 VRChat 配置好的密钥，不会替用户开启或修改服务端双重认证。

登录需要验证时先选择邮箱或 TOTP。仅服务器返回的验证方式可选；客户端不会把保存密钥当成服务端启用 TOTP。选择 TOTP 后输入框默认留空。当前账号保存过密钥时显示「填充验证码」，点击后才解密密钥并生成、填入验证码，随后点击「验证」提交。仍支持手动输入和备用恢复码，不会自动填充或自动提交。

密钥按登录用户名和完整 API 地址隔离。CEF 使用 Windows 当前用户的 DPAPI，Electron 使用 safeStorage；系统密钥库不可用时拒绝保存，不降级为明文。配置数据库仅包含加密内容。密钥不会出现在普通账号密码字段或日志中，发送给 VRChat 的是验证码。删除保存的账号时同时移除对应密钥。密钥受系统用户和桌面宿主约束，复制配置到其他环境后需重新配置或手动验证。

主账号验证完成后才继续批量登录其余账号。副账号同样手动选择方式，验证码通过对应账号的独立 HTTP 客户端提交。取消登录、切换账号或关闭会话后丢弃迟到的结果。

实现参考：[RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)、[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。当前 Electron 40 使用该版本提供的同步 safeStorage 接口。算法使用 RFC 公开测试向量验证；账号隔离、取消、显式填充、倒计时和 Windows 加密分别有自动测试。未使用真实密钥或执行真实账号的登录验证。

本轮验证：103 项相关前端测试、3 项 Windows 加密测试通过，JS 类型检查、架构/依赖/本地化/版本检查及前后端 Release 构建通过。定向 ESLint 仍报告 auth.js 原有的 require 全局定义问题；未改动该多账号运行时入口。测试版使用独立配置目录启动，窗口响应正常。
