## 判断与已有能力

项目适合继续优化，但优先级最高的是让已有功能更容易找到、更可靠、更符合用户的操作预期。下面按使用价值和改动范围排序；不把已有能力重新包装成新功能。

已确认存在：

- `Ctrl+K` 快速搜索、拼音匹配、最近相遇/到访记录；工具也能固定到导航栏。
- 收藏世界跨本地/远程收藏搜索、去重，以及名称/作者和标签搜索模式。
- 自动跟随、桌面/VR/SteamVR 快速启动、状态栏跟随状态和停止入口。
- 桌面通知总开关、自定义声音、托盘静音、V 睡模式。
- 首次欢迎介绍、更新说明、页面 `KeepAlive`、表格排序持久化。
- 好友活动预览和弹窗已接入当前未提交的 `UserDialogActivityTab.vue`；`FriendActivity` 尚无独立路由。已有相关文件不能当成缺失功能重新实现。

已有工作树还包含通知动效、进度条和减少动态效果相关改动。开始实现前先检查 `git status`，不要覆盖这些工作。

## U01：补齐 Ctrl+K 搜索链路（已完成）

**场景：** 用名称搜索世界或已加入的群组；清空关键词后继续看最近遇到的人和最近去过的世界。

**现状证据：** [quickSearch.js](../src/stores/quickSearch.js) 的 `handleWorkerMessage()` 已接收 `ownWorldResults`、`ownGroupResults`、`joinedGroupResults`，但 [QuickSearchDialog.vue](../src/components/QuickSearchDialog.vue) 未展示这些分组，`hasResults` 也未计入它们。`dispatchSearch()` 在空查询时调用 `clearResults()`，连最近记录源数组也清空，随后默认最近列表无法直接恢复。

[quickSearchWorker.js](../src/stores/quickSearchWorker.js) 中裸 `!/@/#` 返回原始索引项；[searchIndex.js](../src/stores/searchIndex.js) 的这些索引项没有 `type`，而 `selectResult()` 依赖该字段打开详情。因此要验证“显示 → 选择 → 打开”的完整链路。

**最小范围：** 复用现有 Worker、结果数组、详情入口；补齐分组与空结果判断，规范前缀查询的结果类型；分开清空查询结果与关闭弹窗释放缓存。`@` 搜索的是缓存世界，不能一律标成“自己的世界”；普通查询与前缀查询的分组名称应反映真实数据来源。

**验收：**

- 只有世界或群组命中时，也能显示、用键盘选择并打开对应详情。
- 裸 `!/@/#` 不出现选择后无响应；大量结果沿用合理上限。
- 输入 → 清空后恢复最近记录；关闭重开仍加载最新最近记录。
- 拼音、收藏去重、过期异步结果丢弃继续有效。

**验证入口：** 扩展 `src/stores/__tests__/quickSearch.test.js`、`quickSearchWorker.test.js` 和 `src/components/__tests__/QuickSearchDialog.test.js`，用最小数据先复现上述缺口。

**本次实现：** `QuickSearchDialog` 已展示自有世界、创建的群组和已加入群组；Worker 对裸 `!/@/#` 结果补齐 `type` 契约；清空关键词只清空当前结果，保留已加载的最近记录。定向测试 3 个文件、11 项通过；相关文件格式检查通过。全仓 JavaScript 类型检查仍有既有错误，见交付说明。

## U02：收藏世界支持短中文关键词

**场景：** 输入“酒吧”“舞厅”“雨”寻找收藏世界。

**现状证据：** [FavoritesWorld.vue](../src/views/Favorites/FavoritesWorld.vue) 的 `hasSearchInput` 判断任意非空输入，`isSearchActive` 和 `doSearchWorldFavorites()` 却要求至少 3 字符。输入 1～2 字时不进入搜索结果，但分组高亮已经按“有输入”处理。

**最小范围：** 统一使用规范化后的非空查询作为本地搜索生效条件，复用 `searchableWorldEntries`、现有去重与 200 ms 防抖。首版不增加远端请求或重做卡片布局。

**验收：**

- “酒吧”“雨”能匹配；空白输入恢复原分组与高亮。
- 中文输入法组合期间体验正常；名称/作者模式和标签模式都适用。
- 本地与远程重复收藏只显示一次；清空输入不残留旧结果。
- 用较大收藏集验证短查询的响应与滚动；有性能问题再单独评估虚拟列表。

**本次实现：** 搜索词统一按去首尾空白、转小写后的非空值启用本地搜索；名称/作者和标签模式都取消 3 字符门槛，继续复用现有收藏去重、防抖和卡片渲染。新增纯过滤逻辑与 1～2 字中文、单字符标签、空白清空回归测试。

## U03：好友列表保留排序与浏览位置

**场景：** 按共同好友数或其他列排序，切到别的页面再回来，继续从原位置查看。

**现状证据：** [FriendList.vue](../src/views/FriendList/FriendList.vue) 的 `applyFriendsListSearchChange()` 无条件执行 `setPageIndex(0)` 和恢复 `friendNumber` 默认排序；路由变化、搜索变化等都会调用它。页面已有 `persistKey: 'friendList'`，[useVrcxVueTable.js](../src/lib/table/useVrcxVueTable.js) 也已有排序持久化，应修复覆盖逻辑。

**最小范围：** 区分修改查询条件与刷新数据：用户改变搜索/筛选时归第一页，保持所选排序；页面返回和普通数据刷新保持有效页码。数据减少时把页码限制在有效范围内。复用现有状态，不另建全局表格存储。

**验收：**

- 输入、清空搜索后排序不变；有效第 3 页返回后仍是第 3 页。
- 好友数量减少时不会停在越界空页；重启后原有排序持久化有效。
- 批量操作勾选仍遵循现有清理规则，不自动恢复删除等操作的旧勾选。

**本次实现：** 搜索和筛选变化仍回到第一页，但不再覆盖用户当前排序；路由返回和好友数据刷新保留有效页码，结果减少时自动限制到最后一页。新增好友列表回归用例，并补齐当前组件测试夹具缺失的 mutual store mock。

**验证入口：** `src/views/FriendList/__tests__/FriendList.test.js` 与 `src/lib/table/__tests__/useVrcxVueTable.test.js`。

## U04：显示 SteamVR 实际启动阶段

**场景：** SteamVR 启动较慢，用户想知道还在启动、已经检测到运行，还是启动失败。

**现状证据：** [QuickLaunchButton.vue](../src/components/QuickLaunchButton.vue) 的 `startSteamVR()` 固定等待 5 秒后直接把运行状态设为 `true`；[LaunchDialog.vue](../src/components/dialogs/LaunchDialog.vue) 也有固定等待。CEF [GameHandler.cs](../Dotnet/AppApi/Cef/GameHandler.cs) 的 `StartSteamVR()` 成功仅表示命令已发出，运行检测是另一个能力；Electron 对应 [GameHandler.cs](../Dotnet/AppApi/Electron/GameHandler.cs)。

**最小范围：** 两个入口复用有总超时的启动等待逻辑，通过已有 `IsSteamVRRunning()` 检测；显示“正在启动 SteamVR / 已检测到运行 / 启动超时”，超时后提供重试。需要继续启动 VRChat 时由用户明确选择。按钮防重复点击，结束后恢复可用。

**验收：**

- 已运行时立即继续；模拟第 8 秒才运行，不会在第 5 秒提前报成功。
- 始终未检测到时进入超时状态，可重试；检测异常不当成成功。
- 快速启动和实例启动一致，不并发启动；退出当前操作后清理局部检测任务。
- 文案只说“检测到运行”；现有进程检测不能证明头显已准备好。

**验证入口：** `src/components/__tests__/QuickLaunchButton.test.js`、`src/components/dialogs/__tests__/LaunchDialog.test.js`。不更改原有全局进程监测周期、启动模式和参数规则。

**本次实现：** 新增共享的 `waitForSteamVRRunning()` 轮询器，启动命令发出后每 500 ms 检测一次，15 秒总超时，并区分已运行、启动中、超时、检测异常和取消。快速启动与启动对话框现在都会显示启动中/检测成功/超时重试状态，检测异常不会被当成成功；等待期间入口按钮会防止重复触发，组件卸载时会取消局部检测任务。新增延迟启动、超时、检测异常和共享等待器回归测试，相关 3 个测试文件共 23 项通过。

## U05：自动跟随可可靠停止，并处理最新目标

**场景：** 好友在加入过程中连续换房，或用户点击停止后不希望继续触发游戏退出/启动。

**现状证据：** [autoFollow.js](../src/stores/autoFollow.js) 的 `runJoin()` 在 `isJoining` 时直接返回，没有保存最新待处理位置；`stopFollow()` 清空状态，但进行中的 `runJoin()` 在异步读取运行状态后没有检查任务是否已失效。桌面路径随后可能调用 `QuitGame()` 和启动操作。实际竞态需先用延迟 Promise 复现。

**最小范围：** 用任务编号使停止/换人后的旧任务失效，在尚未执行的宿主动作前检查；保留一个最新待加入目标，当前任务结束后只处理仍有效的最新目标。复用现有同房判断、目标冷却、`shortName`、状态栏和启动入口，保持 WebSocket 事件编排顺序。

**验收：**

- 加入 A 时位置变为 B、C，最终处理有效的 C。
- 停止后不再发起新的 `QuitGame`、`launchGame`、`TryOpenInstanceInVrc` 调用。
- 更换跟随对象后，旧任务不能接管新任务状态或继续启动。
- 同房、离线后回归和同目标冷却仍有效。

**验证入口：** `src/stores/__tests__/autoFollow.test.js`。取消保证只针对尚未发送的动作，无法撤回已经交给宿主的进程命令。首版不增加另一套自动跟随模式。

**本次实现：** 自动跟随加入任务代次和单项最新目标队列。停止跟随或切换好友后，旧任务会在读取运行时状态或发出 `QuitGame`、`launchGame`、`TryOpenInstanceInVrc` 前失效；同一好友连续换房时只保留最后一个有效目标，当前动作结束后继续处理该目标。停止期间保留进行中的清理状态，宿主动作已经发出后不尝试撤回。新增停止竞态、连续换房和切换好友回归测试，自动跟随测试共 16 项通过。

## U06：信息补全给出可信的结果摘要

**场景：** 扫描结束没有新增 Bio/状态，用户需要知道是“没有变化”，还是部分请求失败；取消后也要看得懂完成了多少。

**现状证据：** [infoFetchCoordinator.js](../src/coordinators/infoFetchCoordinator.js) 只有处理数和变化数，请求重试失败主要写控制台，仍会增加 `done`；取消后回到 `idle`。[ProfileCompletionDialog.vue](../src/views/Tools/dialogs/ProfileCompletionDialog.vue) 展示两阶段进度但没有失败摘要，还包含较多硬编码中文；[StatusBar.vue](../src/components/StatusBar.vue) 的 tooltip 也只展示处理/变化信息。

**最小范围：** 在现有流程上增加开始/结束时间、成功/部分成功/失败/取消摘要。分别记录资料获取、公开简介获取和归档失败，明确 `done` 是“已处理”而非“全部同步成功”；提供“重试失败项”，不重复扫描成功项。把新增及相邻说明放入语言包，面向用户描述任务，不使用“算力引擎”等难理解文案。

**验收：**

- 全成功无变化、部分失败、全失败、用户取消能明确区分。
- 单个目标资料成功但简介失败时正确标为部分成功；统计口径一致。
- 重试只覆盖本次失败项，沿用防重入；取消和异常后 UI 不停留在运行/计算状态。
- 完成摘要可从状态栏查看；重启后如果没有持久化摘要，就明确显示“本次启动尚无结果”。

**边界：** 先不改变抓取节奏、WebSocket 重连间隔或全量同步周期；不把离线期间补全称为完整历史恢复。失败摘要属于当前会话，账户变化时清理，不能借此修改多账户运行时。增加 coordinator 定向测试，覆盖部分失败和取消。

**本次实现：** 信息补全状态现在区分完成无变化、部分失败、全失败和取消，分别记录资料、公开简介及 Bio/状态归档阶段的失败目标；`done` 仅表示目标已处理。对话框和状态栏展示本次摘要，失败项可单独重试且不会重新扫描成功目标。新增 coordinator 测试覆盖成功、部分失败、归档失败和取消；相关状态栏回归保持通过。新增文案已加入中英文语言包。

## U08：限时静音与自动恢复

**场景：** 开会时静音 1 小时，到期恢复原来的通知声音设置。

**现状证据：** [notifications.js](../src/stores/settings/notifications.js) 的 `setTraySilentMode()` 以及 Electron [trayContextMenu.cjs](../src-electron/trayContextMenu.cjs)、CEF [MainForm.cs](../Dotnet/Cef/MainForm.cs) 只有静音布尔开关。现有静音影响系统通知声、自定义音效和 TTS，不能等同于关闭全部可见通知或 VR overlay。

**最小范围：** 增加“静音 15 分钟 / 1 小时 / 手动恢复”和“静音至 HH:mm”。临时静音用到期时间表达，与用户持久静音意图区分；沿用当前声音控制通道。两宿主与 renderer 同步，窗口最小化后仍有效。

**验收：**

- 有效期内相关声音静音，可见通知仍按原设置显示。
- 到期恢复原来的各声音开关，不能一律强制开启；手动恢复立即生效。
- 重启和睡眠唤醒后按到期时间校正。
- 用户后来开启持久静音时，临时计时器不会错误解除；CEF/Electron 状态一致。
